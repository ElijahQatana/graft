# Security

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability, and do not include private calendar data in a report.

Use the repository's private vulnerability reporting flow in the GitHub Security tab. Provide the smallest synthetic reproduction that shows the problem. Do not attach real calendar exports, feed URLs, credentials, tokens, attendee details, meeting links or unredacted logs. A feed URL works like a password for the calendar.

If private vulnerability reporting is unavailable, contact the repository owner through GitHub before sharing details.

## Supported versions

The latest release is supported. Fixes are published as a new release.
